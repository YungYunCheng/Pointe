## 剛修掉的三個

**交易缺口兩處**：撤回調漲、續約已讀標記。都是「兩個寫入該是一件事」，分開的話中間失敗會留下半個狀態。

**押金表名稱錯了。** 程式查 `deposits`，實際叫 `deposit_ledger`——租客帳務頁會直接報錯。

而且實際結構**比我原本假設的好**：它是分類帳（收取／利息／扣除／退還各自一筆），不是單一餘額。所以順手把顯示改成**列出每一筆扣除和它的依據**，不只是一個變小的數字。

> 租客到退租才第一次知道某筆扣除，就是他會爭議的那筆——**而且他應該爭議，因為一個沒有理由附著的數字，沒有人能同意或不同意。**

## 還沒做的

- **Postgres 沒實際跑過。** schema 語法檢查過、外鍵順序對，但沒有真的 Postgres 執行過一次。第一次灌會發現剩下的問題。

- **R2 沒設定。** 證據照片和協議檔案還沒有地方放。

### 需要外部東西的

- **律師核定的租約檔案。** 協議庫是完整的機器，圍著空欄位轉。**沒有它，整套系統跑不完一次完整流程。**
- **Alberta 數字確認**：365 天、90 天通知、各送達方式的視為收到天數、押金上限、退款期限、押金利率。

`web/` 的 18 個工具**還在讀瀏覽器儲存**，只有登入接了 API。接的順序跟後端一樣：`core` → `accounting` → 其餘。
