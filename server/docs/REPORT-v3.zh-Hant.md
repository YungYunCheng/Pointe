### 加人與個別權限

Admin 可以新增帳號，並在角色之上**單獨授予或撤銷**權限。

**撤銷永遠贏過授予**——拿掉權限不該取決於資料列的寫入順序。

**改權限會立刻結束該帳號的登入。** 否則剛被通知失去權限的人，還能用到 session 自然過期。

**Admin 不能改自己的。** 唯一能還原一切的帳號，不該有辦法把自己鎖在外面。

### 排程按角色分流

| | Building Manager | Property Manager |
|---|:--:|:--:|
| 帶看 | ✓ | |
| 交鑰匙 | ✓ | |
| 廠商到場 | ✓ | |
| 簽約 | | ✓ |
| 續約 | | ✓ |
| 前期詢問跟進 | | ✓ |

兩邊都看得到整本行事曆，但只能排自己那類。一個角色只有一個人，「誰都能排」就是兩邊行事曆互相塞滿對方的事。

### 交鑰匙有前置條件

```
PM 確認租約已簽 → BM 才能約時間交鑰匙
```

沒有確認之前，那一戶在交鑰匙清單上顯示「未放行」，**根本沒有時間可以排**。伺服器端也擋。

放行時會記錄押金和首月租金收了沒——**鑰匙一交出去，那兩樣就很難收了。**

會變色的：標頭、選中的分頁、主要按鈕、焦點框、標誌，還有每頁頂端一條 3px 的線。

**四個人共用一台螢幕，其中一個能過帳到總帳——「現在是誰的登入」應該一眼就答得出來，不是讀出來的。**

## 四、員工工具

### 4.1 登入 AuthConsole
四個帳號都有 email 和電話。密碼 182 天到期、前兩週提醒、最近五次不得重複。重設信走佇列且**只走 email**——重設連結發簡訊等於送給拿到手機的人。

密碼雜湊用 **Argon2id**，演算法跟著雜湊一起存，所以換演算法不用叫所有人重設。

### 4.2 出租後台 LeasingConsole
330 戶樓層堆疊、定價、押金、費用、四區車位配額與候補、CSV 匯出、AI 車位建議。

**車位先到先得，配位的讀寫在同一筆交易裡**——兩個人同時登記最後一個車位，只有一個拿到。

### 4.3 名單管理 LeadsCrm
七階段管線、逾時警示、漏斗數據、**重複申請偵測**、**重複記錄合併**。

Email 或電話已在檔案裡 → **硬擋**（Gmail 有正規化）。
姓名相似 70% 以上加聯絡方式部分吻合 → **標記待人工判斷，要填理由**。

後者刻意不自動拒絕：同姓在移民社區極常見，自動用姓名相似度拒絕會系統性打到少數姓氏共用的族群。**「系統說不行」在收到投訴時不是答案。**

### 4.4 排程 Schedule
每日工作清單、前一個工作日提醒、假日表、衝突檢查、**每步驟可發確認**（email／簡訊／兩者）。

**婉拒才是有用的訊號**——時段空出來了該另約，不是跑一趟撲空。

### 4.5 AI 收件匣 AiInbox
三個分頁：收件匣、**需要人處理**、**影子模式**。

六條硬性攔截跑在 AI 之前。22 種意圖對應四個自動化級別，只有 12 種純查詢會自動送出。

**轉人工是寄信不是畫面標記。** 帶四小時時限，同時告訴租客有人接手了。逾期的排最前面。

**影子模式報「會自動送出的那些之中錯了多少」**，不是整體正確率。門檻 2%、至少一百筆。

### 4.6 合約組裝 LeaseIntake
AI 訪談抽取十個欄位、訪談禁區、費用告知快照、押金上限檢查、單位簽約鎖、算出這個租約需要哪幾份協議。

**這個工具不再拼裝租約。**

### 4.7 協議庫 Agreements
Admin 上傳、核准、撤回；PM 使用、發放、發起簽署。含**簽名事件歷程**與**副本雜湊驗證**。

**系統不產生協議。** 生成的條款可能無效，而且讀起來跟有效的一樣專業。要確定租客簽的就是律師核定的，唯一辦法是那兩個是同一個檔案。

### 4.8 文件庫 Documents
範本庫、租客送件核對、簽核閘門。

### 4.9 營運作業台 Operations
帶看確認、遷出六步、扣款清單與異議處理、確認搬離釋出車位、退款期限、**鑰匙放行**。

**扣款流程原封保留：租客有異議時，沒有書面依據和上傳的證據就不能維持扣除。**

### 4.10 現場作業台 BuildingManager
維修工單、廠商排程、入內通知（24 小時閘門是鎖住不是警告）、**進入時段**、**二次提醒**、交鑰匙、**採購單**。

**進入時段是提示不是強制。** 房東在合法通知下仍有進入權，緊急情況也不等方便時段。但硬闖一個租客明說不方便的時間，應該是有人刻意決定的。

### 4.11 採購單 PurchaseOrders
```
BM 開單    →  AI 可從工單起草，只是估價
BM 確認    →  實際金額，有差額要填原因
→ 複製成 Bill →  會計核准，那一步才過帳
```

**採購單不進總帳。那是承諾，不是負債。**

兩段式是因為金額會變。廠商報 $680，牆打開發現止水閥也壞了，開 $745。一段式只能二選一：記一個沒人同意的數字，或整張重打。

### 4.12 投資組合 Portfolio
續約、整備期、定價訊號、業主報表。**四件安靜流失金錢的事，因為之前沒有任何畫面擁有它們。**

續約提前 90 天，**365 天調漲規則在接受決定前就檢查**——窗口內的調漲不只是會被拒絕，可能讓通知整份無效。

整備期顯示**已損失的租金**，不只是天數。

定價只給標記不給建議租金：**市場是這套系統看不到的部分。**

### 4.13 會計 Accounting
見第六節。

### 4.14 變更紀錄 AuditLog
每分鐘比對、機密遮蔽、關鍵字與日期搜尋、CSV／JSON 下載、每次下載記錄 SHA-256。

**快照保留 31 天，變更紀錄永久。** 快照是拿來回檔的，一個月足夠讓錯誤浮現，而且它們很大。變更紀錄很小，而且它存在的理由就是兩年後有人會問。

### 4.15 管理主控台 AdminConsole
帳號、權限、系統健康、資料保留、外寄佇列。

**系統分頁寫出每項壞掉的代價**，不是綠燈紅燈。「沒有 email 服務商」沒有意義；「所有通知、收據、重設連結都在排隊而且沒有一封送到」才有。

## 六、會計模組

102 張表裡有一半是這塊。複式記帳，每筆過帳平衡，已結算期間拒絕新過帳。

### 押金是信託負債

`1020` 信託銀行帳戶必須永遠等於 `2100 + 2110`。儀表板每次載入檢查，不等就變紅。

**把押金記成收入會讓年度數字很好看，然後退租時沒錢可退。** 這是小房東最常見的翻車方式。

### 修訂不是刪除重來

```
發票 4471  v1   $682.50   維修保養        分錄 #118（已沖銷）
                          ↓ 修訂原因：科目編錯
發票 4471  v2   $745.00   電梯保養        #131 沖銷 · #132 新分錄
```

編號和 ID 不變。**不用刪掉重來，也不用重新輸入付款紀錄。**

改到低於已付金額會被擋——那是退款決定不是打錯字。沒填原因不能修訂。

### 對帳兩條不讓步的規則

每一行都要配對得上；結餘要對到分。

**「差一點點也算對完」是差額變成永久且查不到的原因。**

### 管理報酬

4% 給管理公司 + 員工薪資（$30／戶），兩個都可改。

**公式是「一串組件」**，不是單一算式：收入百分比、每戶固定額、每月固定額、每份租約、時薪、分級百分比。可以疊，可以加上下限。

**費率按生效日期版本化。** 六月改成 4.5%，五月照樣用 4%。已過帳的月份不准改。

**畫面上有一個「本月付給管理方多少」的總額**，還有對照收入的實際百分比。**一個看起來是 4% 的安排，把薪資算進去可能是 13.8%——那是業主一年後才會注意到的事。**

系統讀不了合約，所以它記錄「合約說薪資包不包在百分比裡」，如果記錄是「包含」但薪資也在收，畫面會擋一條紅框。

### 薪資的僱傭問題

系統不幫你決定是僱傭還是承攬，因為**決定錯是 CRA 的補稅通知**。

| | 僱員 | 承攬 |
|---|---|---|
| 代扣 | CPP、EI、所得稅 | 無 |
| 雇主負擔 | CPP 對等、EI × 1.4 | 無 |
| $9,900 的實際成本 | 約 $10,700 | $9,900 |

**雇主那一半是加在薪資上面不是含在裡面**——當成含在裡面會低估職位成本約一成。

### 業主分配是現金基礎

```
營運現金 − 未付廠商 − 已過帳未付管理費 − 已過帳未付薪資 − 代收預收租金 − 保留款
```

預收租金在扣除清單裡是刻意的——**那是租客的錢，分掉它就是把下個月的租金花掉了。**

分配過帳到「業主提取」，不是費用。記成費用會低估物業實際賺了多少。

分配前檢查信託帳戶，對不上就先解決——**不然可能分掉的是租客的押金。**

### GST 與折舊

GST 從已過帳分錄算，2300 出、1210 進。**畫面提醒大部分住宅租金免 GST**，數字太大通常是編碼錯而不是真的要繳那麼多。

折舊直線或餘額遞減，每月一筆彙總分錄不是每個資產一筆，**不會折到殘值以下**。

## 七、電子簽名

```
PM 準備 → 寄給租客 → 開文件 → 同意電子簽署 → 簽名 → PM 反簽 → 完成
```

**讓它站得住腳的不是手寫圖案，是稽核軌跡。**

Alberta 的 Electronic Transactions Act 問的是「當事人有沒有同意用電子方式簽」，而「他按了簽名鍵所以應該有同意」不是答案。所以**同意是獨立的一步、單獨記錄**。

**原始檔案永遠不動。** 簽名疊上去產生新檔案，文字不會位移。簽之前驗證原檔雜湊——對不上就停，不是把已經變過的東西簽下去。

**完成證明書接在簽署文件後面**，沒人能只轉發喜歡的那幾頁。含簽署前後兩個雜湊、每個簽署人的同意與簽署時間、來源位址、完整事件序列。

**文件先開，簽名面板後開。** 把筆放在頁面前面的流程，就是有人沒讀就簽的流程。

**「我還不想簽」明著放在頁面上。** 藏起來就是有人簽了不想簽的東西的原因。

完成後**簽署版本寄給每一個簽署人**，不只員工端。

## 八、AI 現在能做什麼

九個任務，**全部在伺服器端執行**。

| 任務 | 用在哪 | 能自行送出？ |
|---|---|---|
| inbox_draft | AI 收件匣 | 僅 12 種查詢意圖 |
| intake_question | 合約組裝 | 否，只填表 |
| entry_notice | 現場作業台 | 否，核准後才送 |
| parking_advice | 出租後台 | 否，給專員的建議 |
| purchase_order | 採購單 | 否，只是估價草稿 |
| report_narrative | 會計月報 | 否，會計核准 |
| change_narrative | 變更日誌 | 否，補充說明 |
| interest_rate | 會計設定 | 否，會計確認才生效 |
| tenant_chat | 租客聊天 | 是，但攔截規則之外才行 |

### 為什麼全在伺服器端

三個理由，照嚴重程度排：

**API key。** 從瀏覽器呼叫，key 會進打包檔——任何人打開開發者工具就拿得到。

**稽核。** 送到租客手上的草稿，應該追得到哪個請求、哪個人、哪個時刻。

**提示詞。** 放伺服器是一份可以審閱的東西；放瀏覽器就是「那個使用者上次載入的版本」。

呼叫端只能說要做什麼、提供事實，**不能用系統的 key 送任意指令給模型**。

### 四條界線

**不決定要不要送出。** 出事時「為什麼這封送出去了」必須能用規則編號回答。

**不寫任何協議文字。** 協議是 Admin 上傳的檔案。產生文件的兩個任務已經刪掉。

**不說任何金額。** 會計月報更嚴格：數字用 SQL 算好，連同推導方式一起給模型，並要求不准重算。

**不設定會影響金錢的參數。** 押金利率由 AI 查、附出處、標信心度，但要人按確認才生效。**AI 給一個看起來合理的錯誤利率，330 筆押金全部算錯，而且要等到有人退租才會發現。**

### 六條硬性攔截

跑在任何 AI 呼叫之前，中英文關鍵詞都有。

| 規則 | 攔什麼 | 為什麼是規則不是判斷 |
|---|---|---|
| R-101 | 收入、AISH、信用、保證人 | 收入來源是受保護特徵，自動回覆會變成差別待遇的書面證據 |
| R-102 | 輪椅、無障礙、服務犬 | 服務動物不是寵物，套用寵物政策等同拒絕調整 |
| R-103 | 種族、宗教、小孩、婚姻、國籍 | 稽核只記規則編號不複製內容 |
| R-104 | 律師、RTDRS、驅逐、投訴 | 爭議中的往來就是證據 |
| R-105 | 租約條款、保留單位、議價 | 具約束力的承諾需要人 |
| R-106 | 漏水、沒暖氣、火災、瓦斯 | 僅租客聊天，回電話不試著回答 |

### AI 不被允許做、目前也沒在做的

- 判斷誰有資格承租
- 閱讀或判讀信用、收入文件
- 給名單排優先順序
- 判定兩個申請人是不是同一個人
- 撰寫或改寫任何協議條款
- 定價或議價
- 核准文件、扣款、退款或任何過帳
- 設定利率或任何影響金錢的參數
- 把維修工單標成加急

### 9.1 最大的一項：前端沒有接 API
